# Zephyr CLI

`zephyr-cli` (command `ze-cli`) deploys prebuilt output and checks a project for Zephyr problems.

```bash
npx zephyr-cli deploy ./dist
```

## Skip mode

Set `ZE_DISABLED=true` to build without Zephyr. No `ze-cli` command contacts Zephyr, reads a token, or needs git information in skip mode.

| Command         | Result with `ZE_DISABLED=true`                                                        |
| --------------- | ------------------------------------------------------------------------------------- |
| `ze-cli run`    | Runs your build command. Does not detect the output. Does not upload.                 |
| `ze-cli deploy` | Does nothing. With `--format json`, prints `{"skipped":true,"reason":"ZE_DISABLED"}`. |
| `ze-cli watch`  | Does nothing. Does not start a watcher.                                               |

Each command prints this line:

```text
The bundle is built. The bundle is not deployed. Zephyr is disabled (ZE_DISABLED).
```

A missing directory or a failed build command still fails. Only the value `true` turns skip mode on. For the full rules, see [CI/CD Automation](/features/automation#build-without-zephyr).

## Doctor

`ze-cli doctor` inspects a project without it installing dependencies, evaluating config files, editing files, building, or deploying. By default it makes no network request and does not authenticate.

```bash
ze-cli doctor [directory] --format text
```

Doctor reports findings. Each finding has a stable `code`. Use the `status`, `exitCode` and finding `code` values in scripts. Do not match message text.

| Exit code | Meaning                                      |
| --------- | -------------------------------------------- |
| `0`       | No error or warning                          |
| `1`       | Errors or warnings found                     |
| `2`       | Invalid project path or root `package.json`  |
| `3`       | Doctor could not complete the read-only scan |

### Online checks

Add `--online` to check that Zephyr works for the project.

```bash
ze-cli doctor [directory] --online [--timeout <milliseconds>] [--format json]
```

The checks send read-only requests, one at a time. Each check has its own limit. The default is `5000` ms. The maximum is `60000` ms. A slow or silent server cannot make doctor hang.

Doctor does not log in, does not exchange tokens, and does not change stored state. Doctor does not delete a token that the server rejects.

| Check         | Question                                                                |
| ------------- | ----------------------------------------------------------------------- |
| `api`         | Does the API (`ZE_API`) answer?                                         |
| `gateway`     | Does the gateway (`ZE_API_GATE`) answer?                                |
| `token`       | Does the gateway accept your token (`ZE_SECRET_TOKEN` or stored login)? |
| `application` | Does Zephyr have a configuration for this application?                  |
| `edge`        | Does the edge URL in that configuration answer?                         |

Each check has the result `passed`, `failed` or `skipped`. A check is `skipped` when an earlier check that it needs has failed. The `findingCode` of the skipped check points to the finding that explains the reason.

`ZE_CI_TOKEN` and `ZE_SERVER_TOKEN` need an exchange before use. Doctor does not exchange them. It reports `ZD0708` (info) and does not check the token.

Doctor takes the application name from `package.json` and the git remote `origin`. If a `zephyr.config` file exists, doctor does not run it. It skips the application and edge checks and reports `ZD0709` (info).

### Online finding codes

Doctor uses a different code for each type of problem: "cannot be reached", "is down", "token not valid" and "configuration not correct".

| Code     | Check            | Meaning                                                            |
| -------- | ---------------- | ------------------------------------------------------------------ |
| `ZD0701` | `api`            | API cannot be reached (network error or timeout)                   |
| `ZD0702` | `api`            | API answered with HTTP 5xx                                         |
| `ZD0703` | `gateway`        | Gateway cannot be reached (network error or timeout)               |
| `ZD0704` | `gateway`        | Gateway answered with HTTP 5xx                                     |
| `ZD0705` | `token`          | No token found                                                     |
| `ZD0706` | `token`          | Token rejected (HTTP 401)                                          |
| `ZD0707` | `token`          | Token not allowed (HTTP 403)                                       |
| `ZD0708` | `token`          | Token not checked (exchange token, or the gateway gave no verdict) |
| `ZD0709` | `application`    | Application name not found, so the application was not checked     |
| `ZD0710` | `application`    | No configuration for this application (HTTP 404)                   |
| `ZD0711` | `application`    | Token cannot read this application (HTTP 403)                      |
| `ZD0712` | `application`    | Configuration answer is not correct                                |
| `ZD0713` | `application`    | Configuration could not be loaded (network error, timeout, 5xx)    |
| `ZD0714` | `edge`           | Edge URL cannot be reached (network error or timeout)              |
| `ZD0715` | `edge`           | Edge URL answered with HTTP 5xx                                    |
| `ZD0716` | `api`, `gateway` | `ZE_API` or `ZE_API_GATE` is not a valid http or https URL         |

Each online finding has a `nextAction`. The values are the same as the MCP values: `none`, `refresh_credentials`, `check_permissions`, `retry_later` and `correct_request`.

### Report format

A report made with `--online` uses `schemaVersion` `1.1.0`. It has an optional `online` object. Findings have the optional fields `check`, `target` and `nextAction`. The `target` is an origin. It is never a path or a token. A token finding names the token source (`ZE_SECRET_TOKEN` or `login`). It never shows the token.

A report made without `--online` does not change. It keeps `schemaVersion` `1.0.0`.

The exit codes do not change. Online errors and warnings exit with `1`. A missing project (`2`) or a tool failure (`3`) has priority over them.

## Options

- `--format <json|text>`: the doctor report format, or the deploy result format (default: `text`)
- `--online`: doctor only. Also check the API, gateway, token, application configuration and edge URL.
- `--timeout <milliseconds>`: doctor `--online` only. The limit for each check (default: `5000`).
- `--verbose`, `-v`: show more output
- `--help`, `-h`: show help
